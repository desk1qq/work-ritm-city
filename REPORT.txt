# Приёмка API "Ритм города"
Команда / дата / версия Python: Даня / 21.11.2026 / Python 3.15.1

## Инварианты и модель переходов
1. Инвариант сохранности после отказа: любой неуспешный запрос (409, 412) не должен изменять данные, версии и не должен добавлять записи в аудит. Реестр ключей не пополняется.
2. Инвариант идемпотентности: точный повтор успешного запроса с тем же ключом возвращает сохраненную квитанцию, не создавая новых версий и записей аудита.
3. Инвариант версионирования: каждая новая успешная операция увеличивает версию ровно на 1 и добавляет ровно 1 запись аудита.

Разница 409 и 412:
409 (OVERLAP, BAD_TRANSITION, KEY_REUSED) - бизнес-конфликт (пересечение времени, запрет смены статуса, неверный повтор ключа).
412 (STALE_VERSION) - конфликт версий, когда клиент пытается изменить данные на основе устаревшей информации.

Модель переходов:
draft - published
draft - cancelled
published - cancelled
cancelled - cancelled
Возврат из cancelled в active запрещен.

## Дефекты
Дефект 1: Сохранение изменений при отказе 409 OVERLAP (Сборка A).
Сборка: A.
Требование контракта: R6 (Любой отказ оставляет ВСЕ записи без изменений).
Предусловия: reset, id 101, версия 1.
Минимальные шаги: PATCH /api/shows/101 If-Match 1, Key K2, {"start":1120}.
Ожидаемый результат: 409 OVERLAP, данные не изменились.
Фактический ответ: 409 OVERLAP, но GET показывает, что start изменился на 1120.
Влияние: при конфликте расписание всё равно ломается.
Номера записей: 6, 7.

Дефект 2: Неверная обработка точного повтора после изменения записи (Сборка A).
Сборка: A.
Требование контракта: R7.
Предусловия: reset, id 101, версия 1.
Минимальные шаги: 
1. PATCH /api/shows/101 If-Match 1, Key K1, {"start":1090}.
2. Повтор PATCH из шага 1 (If-Match 1, Key K1).
Ожидаемый результат: 200 OK с сохраненной квитанцией (версия 2).
Фактический ответ: 200 OK, но версия стала 3, и в аудит добавилась вторая запись.
Влияние: клиент создает дубль операции.
Номера записей: 2, 3, 4.

## Повторный тест и регрессия
Заявлено разработчиком: "В B исправлена повторная обработка операции и запись пересекающихся событий".
Повторный тест (S1, S2): в B сценарии проходят без ошибок. Состояние после отказа не меняется.
Регрессия (S3, S4, S5): в B проверены устаревшая версия и переходы статусов. Ошибок нет.
Дополнительно (S6): В сборке B повтор K1 возвращает сохраненную квитанцию (200), а GET показывает актуальное состояние после K2 (не откатывает запись). В сборке A - ошибка 412.
